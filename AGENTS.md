# AGENTS.md

This file provides guidance to Coding Agent when working with code in this repository.

## Commands

This repo uses **uv** for env/deps (see `docs/DEVELOPMENT.md`). Prefer `uv run`:

```bash
uv sync                                 # .venv + editable install + dev group (pytest, ruff); writes uv.lock
uv run pytest -q                        # full suite (offline: no creds, no network)
uv run pytest -q tests/test_gemini_api.py::test_veo_lro_poll_and_download   # a single test
uv run ruff check src tests scripts     # lint (config in pyproject: line-length 130, py311, ignore E402/E741)
uv run ruff check src tests --fix       # autofix
uv run actionlint                       # lint .github/workflows (a file GitHub rejects fails with *no jobs*)
uv run media-ai image generate --prompt "x" --output /tmp/x.png   # run the CLI (mock by default)
uv run media-ai doctor                  # offline health check of this install
bash install/test_parse.sh              # installer unit tests (CI also runs shellcheck on install/*.sh)
# pip fallback: pip install -e ".[test]" ruff  →  run ruff/pytest/`python -m media_ai` directly
```

Requires Python **3.11+** (uses `tomllib`); `uv` fetches a matching interpreter. ffmpeg + Pillow come bundled via `imageio-ffmpeg`/`pillow` (no system install needed). CI (`.github/workflows/ci.yml`) runs `ruff check` + `pytest -q`. The CLI-integration tests self-skip if Pillow/ffmpeg are absent, so the suite stays green on a bare box.

## Architecture

A provider-agnostic **core**, declarative **binding manifests**, a thin per-provider **adapter** layer, and a thin **CLI** front end. See `docs/ARCHITECTURE.md` for the diagrams; the load-bearing ideas:

- **The unit of integration is a `binding`** — one callable `(provider, model)` pair, id `<provider>/<model>`. The same model through two providers is two bindings, each with its own endpoint, credential, scenes and limits. `provider` names an API surface only; it is not a credential namespace, a routing key, or a config key.
- **Declare the capabilities, code the wire.** A binding's manifest (`src/media_ai/bindings/<provider>.toml`) holds scenes, constraints, lifecycle and auth — and no wire logic. Its adapter (`src/media_ai/providers/<provider>.py`) holds the wire and no capability declarations. Don't reintroduce a second copy of a model's limits in code.
- **Dependency direction is a hard rule:** `core/` never imports `providers/`. Adapters depend on `core/` + `credentials/` + `providers/_http.py`. The CLI depends on `core/` + `registry`, never on a concrete adapter — a manifest's `adapter` field is an import path resolved lazily, which is what lets one live in a private package.
- **`Adapter` (`core/adapter.py`) is transport-agnostic.** `HttpAdapter`/`HttpClient` are an *optional* REST convenience; `transport = "rpc"` gets no base URL, no HTTP client and no status mapping. **An adapter reads no environment variables** — everything it may know about where it is calling comes from its `ResolvedBinding`, so a binding's behaviour is fully described by the config entry naming it.
- **Request flow:** CLI parses argv → normalized request (`core/types.py`) → `derive_scene()` → `resolve()` picks a binding → the binding must serve that scene → `validate_request()` checks the request against the manifest's `Constraints` **before any network call** → `adapter.generate_*()` → one JSON line stamped with `meta.binding` + `meta.scene`. All of it goes through `cli/common.bind()`.
- **A scene is the semantic role of the inputs, not their file type.** `--reference-video` (material to draw on) and `--continue-from` (a clip to carry on from) are different scenes. A capability that does *not* change the input roles is not a scene — Seedream's coordinate editing is a `supports` flag plus a documented technique, because nothing can derive it without parsing prose.
- **Provider-specific features go through `options`**, not new common fields, declared in that binding's `constraints.options`. Per-*binding* knobs (poll intervals, org ids, an inline-upload ceiling) are `[bindings."…".options]` in the config, read via `self.option(...)`. Cross-provider concepts (`--seed`, `--negative-prompt`, `--duration`, `--audio`, geometry) are first-class request fields.
- **Geometry is normalized** (`GeometrySpec`): either pixel `--size WxH` or `--aspect-ratio` + `--resolution` tier. Each adapter maps it to its own wire format; `core/geometry.py` holds the shared primitives.

## Machine contract (do not break casually)

- **stdout = exactly one JSON object**, for success *and* failure. Success carries `artifacts[]` + `usage` + `meta` (incl. `meta.binding` and `meta.scene`). Failure is `{"ok": false, "error": {...}}` with a stable `code`, a usually-runnable `hint`, and `details` naming candidates or alternatives. Human logs go to **stderr only**.
- **Every produced file is in `artifacts[]`, and only there.** The flat `path`/`bytes`/`extra_paths`/`kind`/`task_id` aliases are gone. One call can produce several files (`--count 3`, a timestamps sidecar, a returned last frame), so an alias exposing only the first made silently dropping the rest the easy path.
- **`Scene` is the only taxonomy of "what kind of generation is this".** The `Operation` enum is gone: it merged five video scenes into one value and split one image scene into two, so it could only ever disagree with `Scene`. Nothing restates the scene — `cli/common.stamp()` writes `meta.scene` from `derive_scene()`, and no adapter passes it back.
- **Exit code = error category.** `MediaError` has a `category` → `exit_code` map (`core/errors.py`): `2` CLI · `3` validation/unsupported · `4` auth · `5` rate-limit · `6` provider · `7` timeout · `8` safety · `9` not-found · `1` io/unknown. `cli/common.py::run()` wraps every command to enforce this; make new commands go through `run()`.
- **Result JSON carries `schema_version`.** Bump it in `core/result.py` if you change the shape incompatibly.

## Credentials & secrets (trust boundary)

- The CLI never touches secrets — it names a **binding**; the binding names one credential **reference**; the adapter resolves it lazily and reveals the value **only inside its request builder** (`HttpAdapter._prepare` / `credential().reveal()`).
- **One binding, one source, no fallback** (`credentials/reference.py`): `env://`, `cred://`, `keychain://`, `broker://`, or a registered scheme. The old five-layer precedence chain is gone — it made "where did this key come from?" answerable only by knowing the order and checking five places. Re-resolved per invocation (rotation-friendly).
- A raw key in `config.toml` is refused (that file is the shareable one); raw keys live in the chmod-600 `credentials.toml`, which is refused outright if group- or world-readable.
- `Secret` (`credentials/secret.py`) is reveal-only; its repr/str/pickle render `***` and it isn't JSON-serializable. All log/output/error sinks pass through `redact()` (`credentials/redaction.py`), which masks live secret values + key-shaped tokens. **Never** add a `--api-key` flag, log headers, or serialize a `Secret`.

## Conventions specific to this repo

- **Adding a model requires no code changes; adding a provider requires no core changes.** A sibling model on an existing provider is usually one `[[binding]]` in a manifest. A new provider is a manifest plus an `Adapter` subclass, registered in-process (`register_manifest`) or via a `media_ai.bindings` entry point. `tests/test_manifests.py` enforces the four required answers (provider, model+wire id, scenes+constraints, auth) and checks the adapter imports and implements every declared scene. See `docs/EXTENDING.md`.
- **Nothing falls back.** Resolution refuses — unconfigured, ambiguous, or scene-unsupported all raise with candidates and a hint. The single automatic choice is the scene **default** (`[defaults]`), which exists so a call with neither `--provider` nor `--model` works; those are flags a model may not have learned. Don't add "helpful" substitution, and never let an unconfigured machine reach `mock`: a placeholder returned as `ok: true` is the worst failure this tool can hand an agent.
- **Async is a `Job`.** `video generate --wait false` returns a `JobHandle` whose `poll` string **names the binding** (one provider can serve several). Ark's blocking poll cancels the billed task on SIGTERM/SIGINT/timeout — preserve that when touching `providers/volc_ark.py::_poll`.
- **Usage lines go through `Adapter.record(scene, …)`**, which fills in the binding, provider and wire model. Never call `record_usage` from an adapter: a ledger line that names only a provider cannot be attributed, since one provider serves several bindings at different prices. `summarize_usage` groups by `by_binding` + `by_scene`. On `job query` the scene is genuinely unknowable (the request that implied it belonged to another process) — pass `None` and let the key be **absent**, never guessed.
- **An absent limit is an absent field**, never `0` or `-1`. A sentinel does not make a careless comparison fail; it makes it quietly do the opposite (`w*h > max` with max 0 rejects everything, silently). A range is a `[min, max]` pair only where both ends are always known.
- **`verified` is a date or absent.** It records a real run against the live API; inventing one turns "unknown" into "confirmed".
- **HTTP idempotency:** `HttpClient` retries 429 always, but transient 5xx/network **only on GET/DELETE**, so a POST create-task can't double-submit a billed job. Don't relax this. A provider may supply `retry_classifier(status, body)` to *veto* a would-be retry it knows is pointless (e.g. Ark 429 `QuotaExceeded`); it can only turn a retry off, never on.
- **Only send provider params the caller set.** Optional wire fields with no deliberate default (e.g. Volc `camera_fixed`) are omitted unless provided via `--option`, since some models reject an unrequested parameter. `watermark` is the deliberate exception (defaults to `false` = no watermark).
- **One CLI surface: `media-ai <group> <op>`** (`__main__.py` dispatches to `cli/<group>.py`), **one group per scene group** — `video.*` is `media-ai video`, so joining clips is `video concat`, not a top-level command. That equality is what lets one skill cover exactly one group's scenes. The old per-tool console-scripts (`text2image`, …) and the `mediakit` re-export shim were removed pre-release — there is no compatibility layer to keep in sync.
- **`image edit` declares an intent; it does not select a scene.** It is `image generate` with `--reference` made mandatory, and both run `image.image_to_image`. Keep the guard (a caller who meant to transform an image and forgot the input gets an error, not an unrelated new picture) and do not let it drift into a second code path.
- **A skill describes itself.** Each packaged `SKILL.md` carries `metadata.install`: a `tier` (`core` = always installed and never offered · `optional` = a real choice · `dependency` = pulled in by whatever `needs` it), a one-paragraph human `summary` for the picker, and optional `needs: [...]`. `media-ai init` reads it via `cli/_frontmatter.py` (a YAML *subset* parser — no PyYAML dependency), so adding a skill needs no wizard change.
- **Skills name no models.** A skill says "run `media-ai bindings list`", never "use gemini-3.1-flash-image" — lineups change faster than skill text, and a stale list read confidently is worse than none. Per-binding notes live in `references/bindings/<provider>.<model>.md` and hold only what the manifest cannot: what it is good at, how to prompt it, and its traps. The parameter tables come from `capabilities`.
- **The wizard asks per binding, not per provider.** Three Seedream models are three credential questions — the price of a config that says outright which key each call uses. The menu is generated from the manifests, so a new binding appears in setup with no wizard change; there is no `MODEL_SLOTS` table to maintain.
- **Install has an inverse.** `init` records every destination in `~/.config/media-ai/installed-skills.toml` (`cli/_skillstore.py`); `uninstall` uses it, plus a scan of the conventional agent directories, to find what to remove. Removal only ever touches `media-ai-*` directories holding a `SKILL.md`, and unlinks symlinks instead of following them. **Uninstalling leaves nothing behind** — skills, `config.toml` and `credentials.toml` all go unless a `--keep-*` flag holds one back. Keeping configuration by default would commit the project to *migrating* a file written by any past version, since a reinstall would always find one waiting; removing it is what makes an install a fresh start. (Migration is tracked as its own issue; until then `--keep-config` is the escape hatch, and an interactive run still confirms with the paths spelled out.) `doctor` diagnoses the same installation, strictly offline.
- **The wizard's UI follows clack** (`cli/_prompt.py`): one connected rail (`┌ │ └`), answered steps redrawn as `◇ question` + value, `●`/`○` for pick-one vs `◼`/`◻` for pick-any, cyan = cursor, green = chosen, `box()` for an aside. It degrades to numbered menus without a tty and to ASCII glyphs on a terminal that cannot encode the symbols.
- **Ask everything, then do everything.** `init`/`uninstall` are a list of question steps run by `_prompt.run_steps()`, filling a `_Answers`/`_Choices` dataclass, followed by one apply phase — the only part that touches disk. That is what makes Ctrl-C safe *and* Esc-to-go-back safe (a step gets re-run, so it must not have written). Adding a step means adding a closure to that list, not a write in the middle of the questions. `run_steps` skips back over steps that asked nothing, so flag-driven no-op steps stay invisible to the user. **A step clears the fields it owns before anything else, on every path** — including the ones where it decides it has nothing to ask. Re-running it otherwise leaves the previous answer behind: deselect a provider on the way back and its key would still be written, or `providers` would name one `needed` no longer has and the next step dies on a KeyError. Every question must live in a step, including a confirm you are tempted to ask beside the thing it guards (`--verify`).
- **`copy_skill` is a sync, not a copy.** It deletes files the packaged skill no longer ships. Only adding would strand a dropped reference file, and since "is this current?" compares whole trees, the leftover would make the skill look modified forever — so the installer would re-ask about a collision that updating cannot fix.
- **Esc is back, Ctrl-C is cancel.** `_read_key` waits `_ESC_TAIL_SECONDS` for an escape *sequence* before calling a lone Esc a keypress — reading the tail unconditionally hangs until the next key. Line prompts (cooked mode) take a typed `BACK_TOKENS` word instead.
- **The version lives in one place.** `__version__` in `src/media_ai/__init__.py`; `pyproject.toml` reads it via `dynamic = ["version"]`. The single exception is `DEFAULT_VERSION` in `install/install.sh` — a fallback *git ref*, not a package version — which `tests/test_version.py` pins to it. Don't tag by hand, and don't reintroduce a static version in `pyproject.toml`.
- **Bumping the version is the release.** `release.yml` runs on every push to the default branch, and releases when `__version__` has no matching tag yet — so a merged PR that bumps it (`scripts/bump_version.py 0.3.0`) tests, tags, builds and publishes a pre-release, and one that doesn't exits green. The condition is *"this version is untagged"* rather than *"the version line changed"* on purpose: that answer is the same after a re-run, a squash merge or a force-push, so a half-failed release is just re-run. The number is a human decision; the **direction** isn't — `ci.yml` runs `scripts/check_version.py` on every PR and fails one whose version is behind a released tag, by semver precedence (`0.2.1` and `0.3.0` both follow `0.2.0`; `0.3.0-rc1` precedes `0.3.0`). It needs the tags, hence `fetch-depth: 0` on that checkout. See `docs/DEVELOPMENT.md`.
- **Re-running the installer is a no-op.** A skill whose files already match the packaged copy (`_skillstore.skill_is_current`) is neither rewritten nor asked about, config files are only backed up when the content actually changes, and the installer's self-test redirects `MEDIA_USAGE_LOG` into its scratch dir. Keep it that way: install is also the upgrade path, so anything that accumulates per run is a bug.
- **Live tests are binding-driven.** `tests/test_live.py` asks `capabilities --scene <s> --configured` which bindings this machine can reach and parametrizes over them; `live.yml` configures itself from the env vars each manifest declares (`.github/scripts/configure_live_bindings.py`). Neither holds a list of providers or keys, so adding a binding needs no edit in either — and nothing is exercised that is not genuinely configured.
- **Tests are offline.** Adapters are exercised with a `FakeClient` (`tests/conftest.py`) that records request bodies and returns canned responses; `conftest.adapter_for("<binding id>")` builds one from a binding, because an adapter is constructed from a binding and nothing else. The mock backend covers the local ffmpeg/Pillow path. Real-API calls are never made in CI. New adapters get a mocked-API test (request body + response parse + error mapping); new bindings are auto-covered by `tests/test_contract.py` (every declared scene accepts a minimal request) and `tests/test_manifests.py` (the declaration is well-formed and implemented).
